Hardening and type-surface fixes from the SDKS-5511 review. Note for CommonJS consumers (unchanged by this release): the package has shipped ESM and IIFE only since the 2.x restructure, with no `require` condition in its exports map. CommonJS consumers must load the bundle through the dynamic `import()` of the ESM entry, consume the IIFE bundle (`@forgerock/login-widget/iife` or the unpkg/jsdelivr fields), or stay on ESM. The published entry-point types no longer import a nonexistent `./main.css` (they now point at the documented `@forgerock/login-widget/widget.css` export), `widget.config.d.ts` ships with its internal aliases rewritten like every other declaration, and the release type pipeline fails instead of warning when any expected declaration file is missing. On top of the type surface: the published widget ESM and IIFE builds no longer register or bundle the repo-local e2e canary stage (a new `exclude` option on the `customRegistry` Vite plugin keeps listed subtrees of `custom/components/` out of the generated registry; the npm bundle and `ping-lf init` scaffolds stay clean, while login-app and Storybook builds still register it for the e2e suite). The custom-component import boundary closes several bypasses: Svelte files are reduced to their script blocks and markup expressions with the Svelte compiler before the import scan (markup can no longer desync the parser into missing a forbidden import, and the compiler is resolved so the check keeps working inside Vite's ESM config bundles), `import.meta.glob(...)` (including multiline and generic-typed call sites) and computed dynamic `import(x)` / `require()` calls fail the build with a `forbidden-dynamic` violation, and `.mjs`/`.mts`/`.cjs`/`.cts`/`.jsx`/`.tsx` files are scanned like `.ts`/`.js`/`.svelte`. The registry writes its generated file through a temp+rename so concurrent consumers never read a truncated registry, rejects component names containing control characters, and its dev watcher uses an exact directory boundary. `ping-lf init` now writes a `pnpm-workspace.yaml` that lists `core` and `themes` so the scaffolded `build:framework-core` resolves, and the framework copy shipped by `init`/`update` excludes `.env` and `.env.*` files at any depth plus secret file extensions (`.pem`, `.key`, `.p12`, `.pfx`) and `credentials*` files, not just the repo-root ones. The bundle visualizer now writes `stats.html` outside `dist/` (which is the npm files list) and only when `ANALYZE=1` is set. Component names given to `ping-lf generate` and the MCP `generate_callback`/`generate_stage` tools are now sanitized into a PascalCase identifier before being written into scaffolded files (quotes, comment terminators, markup, and leading digits can no longer break or inject into generated code; a name with no letters fails with a typed error), so a scaffolded multi-word stage name may need its `@component Name` header adjusted to the exact AM stage name.
